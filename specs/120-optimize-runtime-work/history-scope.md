# Scoped project history follow-up

## Requirements and scope

- Typed document edits, gesture grouping, undo, redo, and main-process writers prepare against the affected project graph. A generic whole-project copy is no longer a preparation option.
- Paste source locations are reads. An Instance placement, its library definition, and registration of a new definition have separate effects. Mixed batches still observe patch order and share one undo entry.
- ProjectSession owns the active project. History owns ordered publication, dirty state, retention, rollback, and runtime reconciliation. The render operation owns its stable input and its artifacts.
- Original application code remains under GPL-3.0-or-later. There are no new dependencies, external code, or cross-license source transfers. Project XML and Java-compatible freeze filenames and formats are unchanged. Blue retains committed freeze audio during unfreeze so a saved project, an undo entry, or another object can still use it.

## Implementation and verification

1. Classify paste sources separately and test both orders of a mixed definition and placement edit in the project history round-trip suite.
2. Capture graph identities once per detached scope, then replay the delta into the same canonical owners. Reconstruct mixed gesture endpoints from the union of the recorded scopes. Cover both gesture orders, exact XML, undo/redo, and zero whole-project copies.
3. Give Relink Missing Audio and each Unified Library writer an explicit write scope. Freeze/Unfreeze checks the document, session, revision, project directory, and cancellation after barrier settlement. Verify that rejected attempts remove generated audio and that committed unfreeze preserves audio through undo and redo.
4. Remove the generic fallback and test all four typed history transitions. Retain the same 200 ms p95 budget and the existing history size limits. Use three independent Node performance rounds on the same reference host for each revision. Save raw measurements with the baseline and candidate revision and environment metadata.

| Owner | Event | Outcome |
| --- | --- | --- |
| ProjectHistory | Prepare an edit | Resolve reads and stage changes in patch order within the declared scope. An invalid preparation leaves canonical data and history intact. |
| ProjectHistory | Extend, settle, or cancel a gesture | Merge against the original baseline, publish the resulting history state, and reconcile any runtime outcomes. Cancellation restores the baseline. |
| ProjectHistory | Accept a prepared host mutation | After settlement, recheck authority and limits, then publish the scoped delta once. A stale result is discarded. |
| Freeze operation | Cancel or change project directory before commit | Discard the prepared edit, remove only audio generated by that attempt, and release its render resources. |
| Freeze operation | Commit accepted | Finish the operation and retain audio for canonical, saved, and undoable references. Later cancellation cannot undo the commit. |
