# Implementation Plan: Render to Disk and ScoreObject Freezing Parity

**Branch**: `056-render-freeze-parity` | **Date**: 2026-07-10 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/Users/stevenyi/work/blue-electron/specs/056-render-freeze-parity/spec.md`

## Summary

Implement Java Blue-compatible audio rendering in the Electron main process and Java-compatible ScoreObject freezing around the existing `@blue/data` project model. Ordinary Render to Disk will generate a disk-profile CSD from the canonical project, combine app-wide Disk Render settings with project-owned `ProjectProperties`, execute the configured Csound command, and optionally play or open the verified output. Freeze will render a deep-copied object-scoped temporary project with the separate Utility executable and freeze flags, allocate `freezeN.wav` or `freezeN.aif` in the project directory, inspect duration and channels, then atomically replace or restore score objects while preserving Java-compatible frozen XML.

The design keeps file I/O, subprocesses, dialogs, and IPC in `@blue/app` main/preload code. Pure project-model behavior, frozen-object CSD generation, XML serialization, and audio-header parsing remain browser-safe and Node-free in `@blue/data` where they are reusable and testable.

## Technical Context

**Language/Version**: TypeScript 5.8.x with strict mode; React 19.x; Electron 35.x; Node.js APIs in the Electron main process only
**Primary Dependencies**: `@blue/data`, `@blue/java-runtime`, Electron `dialog`/`shell`/IPC, Node `child_process`/`fs`/`path`, existing program-settings store, existing project snapshot/patch bridge, Vitest 4.x
**Storage**: `.blue` XML remains canonical project persistence; app-wide program settings remain in `program-settings.json`; generated freeze audio is project-relative derived data; temporary CSD files are main-process temporary artifacts
**Testing**: Vitest unit/contract tests in `packages/blue-data` and `packages/blue-app`; existing CSD fixture tests; manual Electron quickstart with an installed Csound executable
**Target Platform**: Electron desktop on macOS, Windows, and Linux, with platform-specific Java-compatible freeze extensions and configured Csound executables
**Project Type**: Electron desktop application with pure data package, main/preload bridge, and React renderer
**Performance Goals**: Rendering and freezing must not block the renderer; one active disk/freeze operation must expose progress and support cancellation; project mutation occurs only after a verified audio artifact exists
**Constraints**: `@blue/data` must not import Node built-ins or UI code; serialized frozen filenames remain relative; normal commands use argv-safe subprocess execution; explicit advanced command overrides preserve Java-compatible command-line behavior; existing CSD export remains distinct from audio rendering
**Scale/Scope**: One active project operation at a time; root and nested PolyObject SoundObjects already supported by the TypeScript port; all Java disk format/sample-format settings; WAV/AIFF metadata inspection for generated freeze artifacts

**Structure Decision**: Use the existing monorepo boundaries. `@blue/data` owns pure frozen-object/CSD/XML/audio-header behavior. `@blue/app` main owns dialogs, settings lookup, subprocess execution, project-directory file operations, progress, cancellation, and canonical mutation. `@blue/app` shared owns serializable IPC contracts and target/result types. The renderer only invokes typed preload methods and displays status/toasts; it never parses XML, chooses executables, or writes artifacts.

## Implementation Approach

1. Establish pure Java-parity data behavior first: nested frozen XML, generated frozen playback notes/instrument, deep-copy temporary render data, and WAV/AIFF metadata parsing.
2. Build and test a pure disk command planner that encodes the three-layer settings contract, normal format toggles, message flags, project advanced settings, complete override behavior, and platform-independent path handling.
3. Add main-process render orchestration with generated disk CSD, Csound subprocess lifecycle, streamed status, cancellation, output verification, and optional play/open follow-up commands.
4. Add main-process freeze orchestration with Java filename allocation, object-scoped rendering, metadata inspection, atomic replacement/restoration, recursive reference counting, and project-relative cleanup.
5. Add typed preload IPC, menu/context-menu wiring, project snapshot broadcasts, status UI, and regression coverage for each user story.

## Dependencies and Ordering

- Pure `@blue/data` XML/CSD/metadata behavior blocks reliable freeze and disk integration.
- Disk command planning and IPC contracts block main-process orchestration.
- Main orchestration blocks menu and context-menu integration.
- Serialization and command tests can run in parallel once their pure modules are defined; end-to-end/manual verification waits for all layers.

## Final Implementation Notes

- Main-process ownership remained intact: dialogs, executable selection, subprocess lifetime, output verification, filename allocation, artifact deletion, and canonical project mutation live in `@blue/app` main.
- `@blue/data` now owns browser-safe FrozenSoundObject XML/CSD behavior, deep-copied freeze render data, and WAV/AIFF metadata interpretation. The metadata result identifies its actual container format so a `.wav`/`.aif` freeze artifact cannot be committed with the wrong platform format.
- Disk and freeze CSD generation reuse the active project JavaScript session and, when present, the active Java runtime client for Python and Clojure objects. This preserves shared interpreter state instead of evaluating an isolated object copy in a fresh context.
- Multi-target freeze/unfreeze stages every render and replacement before mutating the canonical score. Any rejected target, render failure, invalid artifact, cancellation, or stale target rolls back generated artifacts and leaves all selected source objects in place.
- Project updates are broadcast after the single canonical commit. Renderer operation IDs prevent late IPC status messages from reviving a settled toast, and terminal toasts clear stale percentages.
- Frozen timeline/editor integration uses the existing project-relative artifact key. AIFF PCM has a direct waveform summary path, and waveform paths divide Java Blue's `rowHeight - 4` inner area evenly across channels.
- Java's default distinction is preserved: `ProjectProperties` itself defaults `diskUseZeroDbFS` to false for legacy/missing XML, while a new project is seeded from Program Disk Render, whose default is true.
